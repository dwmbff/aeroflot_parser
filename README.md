# Aeroflot XPath Checker

Скрипт для автоматической проверки наличия HTML-элементов на сайте
[aeroflot.ru](https://aeroflot.ru) по заданным xpath. Если элемент не найден — фиксирует это в
логе и с помощью ИИ (через [OpenRouter API](https://openrouter.ai/)) ищет альтернативный xpath на
актуальной странице.

---

## Что делает скрипт

1. Открывает главную страницу `aeroflot.ru`
2. Проходит сценарий поиска авиабилетов: заполняет «Откуда»/«Куда»,
   выбирает дату в календаре, нажимает «Поиск»
3. На каждом этапе сценария проверяет наличие элементов по xpath из
   `elements.json`
4. Если элемент не найден — получает HTML страницы, отправляет его в ИИ
   (модель `openai/gpt-oss-120b:free` через OpenRouter) и пытается найти
   актуальную замену
5. Формирует три выходных файла: `log.txt`, `new_xpath.txt` и
   `ANALYTICS.md`

Подробное пошаговое описание логики — в [`ANALYTICS.md`](./ANALYTICS.md).

## Структура проекта

| Файл/Папка | Описание |
|---|---|
| `elements.json` | список элементов и их xpath, с этапами сценария |
| `config.py` | настройки (URL, город, таймауты, ключ API) |
| `browser.py` | управление браузером (Playwright): навигация, клики, календарь, ожидания |
| `checker.py` | проверка элементов по xpath, запись в `log.txt` |
| `ai_fallback.py` | обращение к OpenRouter API, поиск альтернативного xpath, запись в `new_xpath.txt` |
| `main.py` | точка входа, оркестрация всего сценария |
| `test_openrouter.py` | отдельный скрипт для диагностики ключа OpenRouter |
| `ANALYTICS.md` | аналитическое описание работы скрипта |
| `requirements.txt` | зависимости проекта |
| `.env.example` | шаблон переменных окружения |
| `log.txt` | результат последнего прогона |
| `new_xpath.txt` | найденные ИИ альтернативные xpath |
| `demo/` | демонстрация работы AI-фолбэка на реальном кейсе |
| `demo/log_demo_ai_fallback.txt` | лог демонстрации AI-фолбэка |
| `demo/new_xpath_demo.txt` | найденные xpath из демонстрации |

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # Linux/macOS

pip install -r requirements.txt
playwright install chromium
```

---

## Настройка

Скопируйте `.env.example` в `.env` и заполните:

```env
OPENROUTER_API_KEY=ваш_ключ_с_openrouter.ai
OPENROUTER_MODEL=openai/gpt-oss-120b:free
```

Ключ можно получить бесплатно на [openrouter.ai/keys](https://openrouter.ai/keys).

Остальные параметры в `.env` не обязательны — есть значения по умолчанию
(город отправления/назначения, дата, таймауты).

---

## Запуск

### Проверить, что ключ OpenRouter работает:

```bash
python test_openrouter.py
```

### Полный прогон сценария (с видимым браузером, для отладки):

```bash
python main.py
```

### Полный прогон без UI браузера (для финальной проверки/CI):

```bash
python main.py --headless
```

### Тест механизма AI-фолбэка (искусственно ломает один элемент и проверяет, что ИИ находит замену):

```bash
python main.py --force-test-ai
```

## Выходные файлы

| Файл | Описание |
|---|---|
| `log.txt` | построчный журнал прогона: `[OK]`, `[MISSING]`, `[OK - not present, optional]`, `[SKIPPED - alt flow active]`, а также служебные события (`[EVENT]`) и записи по обращениям к ИИ (`[AI_OK]`, `[AI_API_ERROR]`, `[AI_FALLBACK_FAILED]`) |
| `new_xpath.txt` | найденные ИИ альтернативы в формате: `имя_элемента \| старый_xpath \| новый_xpath \| уровень_уверенности` |
| `ANALYTICS.md` | пошаговое описание логики скрипта для проверяющего |

## Демонстрация AI-фолбэка

Папка `demo/` содержит результаты прогона, в котором xpath одного из
элементов (`price_1a_econom_basic`) был намеренно испорчен — для
демонстрации того, что механизм поиска альтернативного xpath через ИИ
реально работает на актуальной странице сайта, а не только в теории.

---

## Известные ограничения

Полный список — в разделе 6 [`ANALYTICS.md`](./ANALYTICS.md). Кратко: скрипт рассчитан на
один маршрут и одну дату за прогон, часть xpath завязана на текущую
вёрстку сайта, а бесплатная модель ИИ имеет ограничения по частоте
запросов (обрабатывается автоматическими повторными попытками).
