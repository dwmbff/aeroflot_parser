# Аналитический документ: скрипт проверки xpath-элементов Аэрофлота

## 1. Цель скрипта

Скрипт автоматически проходит сценарий поиска авиабилетов на сайте
aeroflot.ru и проверяет, что все важные элементы интерфейса (поля ввода,
кнопки, календарь, результаты поиска) находятся на своих местах по заданным
xpath. Если элемент не найден — это фиксируется в логе, а скрипт с помощью
ИИ пытается найти актуальную замену устаревшему xpath.

## 2. Какой сценарий проходит скрипт

1. Открывает главную страницу сайта, закрывает баннер cookie при необходимости
2. Заполняет поле «Откуда» (Москва), выбирает город из подсказок
3. Заполняет поле «Куда» (Санкт-Петербург), выбирает город из подсказок
4. Открывает календарь и последовательно выбирает дату вылета и дату
   возврата (календарь один общий, сам переключается на выбор второй
   даты после первого клика)
5. Нажимает кнопку «Поиск»
6. Дожидается результатов поиска — либо появляются рейсы, либо сообщение
   об их отсутствии
7. Если рейсы найдены — проверяет тарифы для обоих направлений:
    - Ветка «Туда»: клик по результату → просмотр цен «Эконом Базовый» /
      «Эконом Оптимум» для рейса вылета
    - Ветка «Обратно»: раскрытие панели тарифов для рейса возврата,
      показанного на той же странице без перезагрузки

## 3. Как происходит проверка элементов

Список элементов и их xpath хранится в файле elements.json. Для каждого
элемента указано:
- на каком этапе сценария он должен проверяться,
- нужно ли перед проверкой выполнить какое-то действие (например, сначала
  открыть календарь),
- является ли элемент опциональным (например, попап, который появляется не
  всегда).
  
Пример структуры элемента в `elements.json`:

```json
{
  "name": "price_1a_econom_basic",
  "xpath": "//div[@role='listitem'][.//p[normalize-space()='Эконом Базовый']]//p[contains(text(),'₽')]",
  "stage": "results_flow_1",
  "action_before": "click_after_results_1",
  "notes": "Цена «Эконом Базовый», ветка 1"
}
```
Скрипт проверяет каждый элемент строго в тот момент сценария, когда он
должен быть доступен на странице — это важно, потому что часть элементов
(например, ячейки календаря или строки результатов поиска) физически
отсутствуют в HTML до совершения определённых действий.

## 4. Как работает поиск альтернативного xpath через ИИ

Если элемент не найден по заданному xpath, скрипт:
1. Получает полный HTML текущей страницы
2. Убирает из него служебный код (скрипты, стили, комментарии) и обрезает
   до релевантного фрагмента, чтобы уместиться в лимит модели
3. Отправляет запрос в OpenRouter API (бесплатная модель
   openai/gpt-oss-120b:free) с описанием искомого элемента и очищенным HTML
4. Модель анализирует структуру страницы и возвращает наиболее вероятный
   новый xpath вместе с уровнем уверенности (высокий/средний/низкий) и
   кратким объяснением
5. Если модель нашла подходящий элемент — результат записывается в
   new_xpath.txt

Скрипт устойчив к временной перегрузке бесплатной модели (ошибка 429) —
при такой ошибке делается повторная попытка запроса с паузой.

Механизм был протестирован на реальном кейсе: при намеренной порче xpath
элемента цены тарифа «Эконом Базовый» модель проанализировала актуальный
HTML страницы результатов поиска и корректно определила новый xpath на
основе относительного расположения элементов в разметке (найдя ближайший
элемент с ценой после названия тарифа). Результат этого теста сохранён в
папке demo/ вместе с log.txt и new_xpath.txt для этого прогона.

Пример реального срабатывания механизма (из `demo/log_demo_ai_fallback.txt`):
```
[MISSING] price_1a_econom_basic: //div[@role='listitem'][.//p[normalize-space()='Эконом Базовый']]//p[contains(text(),'₽')]/span[999]
[AI_OK] price_1a_econom_basic: reasoning=Элемент с названием тарифа 'Эконом Базовый' 
найден в <p class='sc-bRKDuR eoDmwD'>. Сразу после него в разметке находится 
<p class='sc-bRKDuR gfyskF'>от 5 628 ₽</p>, содержащий цену...
```

Результат в `new_xpath.txt`:
```
price_1a_econom_basic | //div[@role='listitem'][.//p[normalize-space()='Эконом Базовый']]//p[contains(text(),'₽')]/span[999] | //p[normalize-space()='Эконом Базовый']/following::p[contains(text(),'₽')][1] | high
```

## 5. Выходные файлы

- **log.txt** — полный журнал прогона: какие элементы найдены (OK), какие
  отсутствуют (MISSING), какие пропущены как неактивная альтернативная
  ветка (SKIPPED), какие являются штатно отсутствующими опциональными
  элементами, а также служебные события (запуск, попапы, ошибки, обращения
  к ИИ)
- **new_xpath.txt** — список элементов, для которых ИИ нашёл замену
  устаревшему xpath, в формате:
  `имя_элемента | старый_xpath | новый_xpath | уровень_уверенности`

Пример фрагмента log.txt:

```
[2026-07-04 00:30:07] [OK] from_input: /html/body/div/.../input
[2026-07-04 00:30:26] [OK - not present, branch inactive] no_flights_message: ...
[2026-07-04 00:31:46] [MISSING] price_1a_econom_basic: ...
```
## 6. Известные ограничения

- Скрипт проверяет один конкретный маршрут (Москва → Санкт-Петербург) и одну
  дату — для полной проверки других маршрутов потребуется несколько прогонов
- xpath с фиксированными числовыми индексами в пути (например, div[3])
  хрупки к изменению вёрстки сайта сильнее, чем xpath на основе текста или
  атрибутов
- Бесплатная модель ИИ имеет ограничения по количеству запросов в единицу
  времени, при массовых сбоях xpath (много элементов сразу) время работы
  скрипта может увеличиться из-за повторных попыток
- Некоторые элементы страницы результатов (например, панель альтернативного
  отображения тарифов) подгружаются с задержкой до 60 секунд после появления
  основного списка рейсов. Скрипт учитывает это через увеличенное время
  ожидания перед взаимодействием с такими элементами, но при аномально
  медленной загрузке сайта возможны повторные попытки, что отражается
  в log.txt как информационные события, не влияющие на итоговый результат
- Точность подбора альтернативного xpath моделью ИИ не гарантирована на
  100% — рекомендуется вручную проверять результаты с низким уровнем
  уверенности (confidence=low) перед использованием в продакшене
