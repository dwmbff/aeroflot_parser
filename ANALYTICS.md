## 1. Цель и задача

Скрипт автоматически проверяет, что ключевые элементы интерфейса сайта
aeroflot.ru (поля ввода городов, календарь, кнопка поиска, карточки
тарифов) находятся на своих местах по заданным xpath. Так как xpath жёстко
привязан к структуре HTML-кода страницы, он может «сломаться» при любом
обновлении вёрстки сайта — скрипт обнаруживает такие поломки автоматически
и пытается найти замену устаревшему xpath с помощью ИИ, без участия
человека.

Задача решена: крипт не просто
проверяет статичную страницу, а самостоятельно проходит реальный сценарий
пользователя (поиск авиабилетов туда-обратно), потому что часть элементов
физически появляется в HTML только после определённых действий
(открытие календаря, нажатие кнопки поиска и т.д.).

## 2. Общая архитектура решения

Скрипт написан на Python с использованием библиотеки **Playwright** —
инструмента для автоматизации браузера. Обычная библиотека для скачивания
HTML (requests, BeautifulSoup) здесь не подходит, потому что сайт
Аэрофлота — динамическое одностраничное приложение (SPA): значительная
часть контента (результаты поиска, цены, календарь) генерируется
JavaScript-ом уже в браузере пользователя, а не приходит в готовом виде
с сервера.

Общая схема работы:
```launch_browser()
↓
[search_form]  →  проверка полей «Откуда»/«Куда», календаря, кнопки поиска
↓
fill_from_input() / fill_to_input()  →  заполнение городов
↓
open_calendar() → select_date() ×2  →  выбор даты вылета и даты возврата
↓
click_search()
↓
wait_results_ready()  →  ветка «рейсы найдены» ИЛИ «рейсов нет»
↓
results_flow_1 (ТУДА)  →  проверка тарифов рейса вылета
↓
results_flow_2 (ОБРАТНО)  →  проверка тарифов рейса возврата
↓
После каждой стадии: MISSING-элементы → ИИ (xpath проверяется на странице)
↓
log.txt + new_xpath.txt
```
Между каждым крупным шагом сценария скрипт дополнительно проверяет, не
появился ли на странице всплывающий попап или сообщение об ошибке, и
обрабатывает их — это защищает сценарий от неожиданной остановки из-за
случайного баннера.

## 3. Пошаговый сценарий работы на сайте

| № | Шаг | Что происходит |
|---|-----|-----------------|
| 1 | Открытие сайта | `https://www.aeroflot.ru/ru-ru/`, закрытие cookie-баннера |
| 2 | Заполнение «Откуда» | Ввод «Москва», выбор города из выпадающих подсказок |
| 3 | Заполнение «Куда» | Ввод «Санкт-Петербург», выбор города из подсказок |
| 4 | Открытие календаря | Клик по полю даты открывает единый календарь на 10 месяцев |
| 5 | Выбор даты вылета | Скрипт находит нужный месяц (при необходимости прокручивает ленту месяцев) и кликает нужный день |
| 6 | Выбор даты возврата | Календарь не закрывается и сам переключается на выбор второй даты — скрипт кликает второй день в том же календаре |
| 7 | Нажатие «Поиск» | Клик по кнопке запускает загрузку результатов |
| 8 | Ожидание результатов | Скрипт ждёт либо индикатор готовности результатов, либо сообщение «рейсов нет» |
| 9 | Ветка «ТУДА» | Клик по карточке первого рейса вылета → раскрываются тарифы «Эконом Базовый» / «Эконом Оптимум» с ценами |
| 10 | Ветка «ОБРАТНО» | На той же странице, без перезагрузки, раскрывается аналогичная карточка тарифов для рейса возврата |

Важная деталь, обнаруженная в процессе тестирования: поле «Обратно» на
форме — это не отдельный элемент со своим независимым календарём, а лишь
второе визуальное поле в общей форме дат. Календарь остаётся физически
одним и тем же на протяжении всего выбора обеих дат.

## 4. Как устроена проверка элементов (elements.json)

Список из 20 проверяемых элементов и их xpath хранится в файле
`elements.json`. Для каждого элемента указано:

```json
{
  "name": "price_1a_econom_basic",
  "xpath": "//div[@role='listitem'][.//p[normalize-space()='Эконом Базовый']]//p[contains(text(),'₽')]",
  "stage": "results_flow_1",
  "action_before": "click_after_results_1",
  "fallbacks": ["button:has-text(\"Эконом\") >> nth=0"],
  "optional": false,
  "notes": "Цена «Эконом Базовый», ветка ТУДА"
}
```

- **stage** — этап сценария, на котором должна проводиться проверка
  (search_form, calendar, results_flow_1, results_flow_2 и т.д.)
- **fallbacks** — запасные селекторы по смыслу (placeholder, текст, роль),
  которые используются, если основной xpath перестал работать
- **action_before** — действие, которое должно быть выполнено ДО
  проверки этого элемента (например, элемент проверяется только после
  клика по карточке рейса)


Такая структура нужна потому, что часть элементов физически не
существует в DOM до совершения определённых действий пользователя —
попытка проверить их раньше времени дала бы ложный `MISSING`.

Пример вывода при проверке (реальный фрагмент из log.txt):
```[OK] from_input: /html/body/div/div[2]/div/.../input
[OK] to_input: /html/body/div/div[2]/div/.../input
[OK] search_btn: /html/body/div/div[2]/.../button
[OK] click_after_results_1: (//button[.//p[normalize-space(.)='Эконом']])[1]
[OK] price_1a_econom_basic: //div[@role='listitem']...
```

## 4.1. Устойчивость к смене вёрстки (resolver.py)

Сценарий не зависит от точного положения элементов в DOM. Каждое действие
(ввод города, клик по календарю, кнопка «Найти», клики в результатах)
ищет элемент через `resolver.py` в три шага:

1. xpath из `elements.json`;
2. запасные селекторы `fallbacks` (по placeholder, тексту и роли);
3. ИИ — подбирает новый xpath по HTML страницы; найденный путь
   проверяется на странице и подставляется в сценарий.

Если основной xpath сломан, но элемент найден запасным путём, сценарий
идёт дальше, а в отчёте элемент остаётся `MISSING` (устаревший xpath
нужно обновить) и код возврата — 1. Календарь не использует классы и
индексы колонок: скрипт идёт по DOM, запоминает последний заголовок
месяца и сопоставляет с ним кнопки-числа.

## 5. Обработка попапов и ошибок

Между шагами сценария скрипт проверяет два типа непредвиденных состояний
страницы:

- **popup_ok_btn** — всплывающий попап с кнопкой «Хорошо» (например,
  подтверждение действия). Если он не появился — это штатная ситуация
  (`optional: true`), не ошибка.
- **something_went_wrong_title / something_went_wrong_box** — блок
  с ошибкой «Что-то пошло не так». Скрипт считает ошибку подтверждённой
  только при видимом заголовке этого блока — сам по себе `box`-контейнер
  слишком общий xpath и даёт ложные срабатывания на обычной странице,
  поэтому проверка box дополнительно требует одновременной видимости
  заголовка.

Пример корректной обработки штатного отсутствия попапа:
[OK - not present, optional] popup_ok_btn: //button[.//span[normalize-space()='Хорошо']...
[OK - not present, optional] something_went_wrong_title: //*[self::h2 or self::h3]...

## 6. Механизм поиска альтернативного xpath через ИИ

Если элемент не найден по заданному xpath, срабатывает следующая цепочка
действий (модуль `ai_fallback.py`):

1. **Получение HTML** — скрипт забирает полный HTML текущей страницы
   (`page.content()`) в момент, когда элемент должен был быть, но не найден
2. **Очистка HTML** — удаляются `<script>`, `<style>` и HTML-комментарии,
   чтобы не тратить лимит модели на бесполезный код
3. **Обрезка HTML** — если после очистки HTML всё ещё больше ~15000
   символов, скрипт ищет в тексте ключевые слова из описания элемента
   (например, «Эконом Базовый» из поля notes) и вырезает фрагмент HTML
   вокруг найденного совпадения (±7500 символов). Если совпадений не
   найдено — берётся начало содержимого `<body>`
4. **Запрос к модели** — очищенный HTML вместе с именем элемента, старым
   xpath и описанием отправляется в OpenRouter API, модель
   `google/gemma-4-31b-it:free` (меняется в `.env`). Промт явно просит вернуть только JSON без
   markdown-разметки
5. **Разбор ответа** — модель возвращает `{"found": true/false, 
   "new_xpath": "...", "confidence": "high/medium/low", "reasoning": "..."}`
6. **Устойчивость к перегрузке** — бесплатные модели OpenRouter иногда
   временно перегружены (ошибка 429 Too Many Requests); скрипт делает
   до 3 попыток с нарастающей паузой (3 с, 6 с)
7. **Проверка и запись результата** — если модель нашла подходящий
   элемент (`found: true`), xpath проверяется на странице (должен найти
   видимый элемент), подставляется в сценарий и записывается в
   `new_xpath.txt`. Если нет —
   в `log.txt` фиксируется `AI_FALLBACK_FAILED` с причиной

## 7. Пример реального срабатывания AI-фолбэка

Механизм был протестирован не только в теории, но и на реальном кейсе:
xpath элемента `price_1a_econom_basic` был намеренно испорчен (дописан
несуществующий узел `/span[999]`), после чего запущен обычный прогон
скрипта на реальной странице сайта.

**Шаг 1 — элемент не найден:**
`[MISSING] price_1a_econom_basic: //div[@role='listitem'][.//p[normalize-space()='Эконом Базовый']]//p[contains(text(),'₽')]/span[999]
`

**Шаг 2 — запрос уходит в ИИ, модель анализирует актуальный HTML и
отвечает:**
`[AI_OK] price_1a_econom_basic: reasoning=В разметке найден блок с текстом
«Эконом Базовый». Внутри него присутствует элемент p, содержащий символ ₽,
но конкретный span-элемент с ценой не указан явно в предоставленном
фрагменте. Поэтому предлагается использовать последний span внутри этого
p, что обычно соответствует ценовому тегу.`

**Шаг 3 — полный сырой ответ модели сохраняется для аудита:**
```json
{
  "found": true,
  "new_xpath": "//div[contains(@class,'sc-ggWZvA')][.//p[normalize-space()='Эконом Базовый']]//p[contains(text(),'₽')]/span[last()]",
  "confidence": "medium",
  "reasoning": "..."
}
```

**Шаг 4 — итоговая запись в new_xpath.txt:**
`price_1a_econom_basic | //div[@role='listitem'][.//p[normalize-space()='Эконом Базовый']]//p[contains(text(),'₽')]/span[999] | //div[contains(@class,'sc-ggWZvA')][.//p[normalize-space()='Эконом Базовый']]//p[contains(text(),'₽')]/span[last()] | medium
`

Важно: модель честно вернула `confidence: medium`, а не
максимальную уверенность — потому что конкретный `span` с ценой не был
явно выделен в обрезанном фрагменте HTML, и модель выбрала наиболее
вероятный вариант, прозрачно объяснив логику выбора. Это ожидаемое и
корректное поведение: результаты с невысокой уверенностью помечены как
таковые и требуют проверки человеком перед использованием в продакшене.

_Полные лог и результат этого теста сохранены в [demo/log_demo_ai_fallback.txt](demo/log_demo_ai_fallback.txt)
и [demo/new_xpath_demo.txt](demo/new_xpath_demo.txt)`._

## 8. Выходные файлы: формат и примеры

### log.txt

Построчный журнал прогона со следующими типами записей:

| Метка | Значение |
|-------|----------|
| `[OK]` | Элемент найден по заданному xpath |
| `[OK - not present, optional]` | Опциональный элемент отсутствует — это штатно |
| `[OK - not present, branch inactive]` | Элемент альтернативной ветки, не активной в этом прогоне |
| `[MISSING]` | Элемент не найден, требуется AI-фолбэк |
| `[SKIPPED - alt flow active]` | Пропущено, так как альтернативная ветка уже активна |
| `[EVENT]` | Служебное событие: запуск, попап, ошибка, повторная попытка клика |
| `[AI_OK]` | ИИ успешно нашёл альтернативный xpath, с объяснением |
| `[AI_RAW]` | Полный необработанный JSON-ответ модели |
| `[AI_API_ERROR]` | Ошибка при обращении к API (сеть, авторизация, rate limit) |
| `[AI_FALLBACK_FAILED]` | ИИ не смог найти подходящий элемент |

Пример фрагмента:
[2026-07-11 16:35:26] [MISSING] price_1a_econom_basic: //div[@role='listitem']...
[2026-07-11 16:35:44] [AI_OK] price_1a_econom_basic: reasoning=...
[2026-07-11 16:35:44] [EVENT] Сценарий завершён: OK=18, MISSING=1, AI=1

### new_xpath.txt

Формат одной строки на найденный элемент:
имя_элемента | старый_xpath | новый_xpath | уровень_уверенности

Пример:
`price_1a_econom_basic | //div[@role='listitem']...//span[999] | //div[contains(@class,'sc-ggWZvA')]...//span[last()] | medium
`

## 10. Технические решения и почему выбраны именно они

- **Playwright вместо requests/BeautifulSoup** — сайт динамический (SPA),
  контент генерируется JavaScript в браузере, статичным парсером его не
  получить
- **Retry с ожиданием видимости перед кликом** — часть элементов на сайте
  подгружается с задержкой до 60 секунд после появления основного списка
  результатов (цены по конкретным тарифам загружаются отдельным, более
  медленным запросом); наивный немедленный клик по xpath приводил к
  таймауту, поэтому добавлено раздельное ожидание появления элемента в
  DOM и ожидание его кликабельности
- **Обрезка HTML по ключевым словам перед отправкой в ИИ** — полный HTML
  страницы может занимать сотни тысяч символов, что превышает разумный
  лимит модели и увеличивает стоимость/время запроса; вместо отправки
  всего документа скрипт находит релевантный фрагмент по текстовым меткам
  из описания элемента
- **Retry на HTTP 429** — бесплатные модели OpenRouter имеют разделяемый
  лимит запросов между всеми пользователями; временная перегрузка
  (`rate-limited upstream`) не является постоянной ошибкой и обычно
  разрешается за несколько секунд
- **Разделение stage/action_before** — позволяет точно моделировать, в
  какой момент сценария каждый элемент реально должен появиться в DOM,
  избегая ложных срабатываний из-за преждевременной проверки

## 11. Известные ограничения

- Часть xpath результатов поиска (`no_flights_message`, `something_went_wrong_box`)
  остаётся абсолютной; для них нет запасных селекторов, и при смене
  вёрстки они уходят в ИИ
- Бесплатная модель ИИ имеет разделяемый лимит запросов между всеми
  пользователями OpenRouter; при массовых одновременных сбоях xpath время
  работы скрипта может увеличиться из-за повторных попыток
- Некоторые элементы страницы результатов подгружаются с заметной
  задержкой (до 60 секунд) после появления основного списка рейсов — при
  аномально медленной загрузке сайта возможны повторные попытки клика,
  что фиксируется в `log.txt` как информационные `[EVENT]`-записи, не
  влияющие на итоговый результат проверки
- Точность подбора альтернативного xpath моделью ИИ не гарантирована на
  100%; результаты с `confidence: low` или `medium` рекомендуется
  проверять вручную перед использованием в продакшене


## 12. Как запустить скрипт

```bash
# Установка
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
playwright install chromium

# Настройка (скопировать .env.example → .env, вписать ключ OpenRouter)

# Проверка ключа API
python test_openrouter.py

# Запуск с видимым браузером (отладка)
python main.py

# Запуск без интерфейса браузера (финальная проверка)
python main.py --headless

# Юнит-тесты (без браузера и сети)
python -m unittest discover -s tests

# Тест механизма AI-фолбэка на искусственно сломанном элементе
python main.py --force-test-ai
```
